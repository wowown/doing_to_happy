# 训练记录 · 自己用的健身重量本

一个单页应用，记每次训练的动作、组数、重量、次数，自动算容量、PR 和进步曲线；另有一块记体重。
数据只存在你打开它的那个浏览器里，不上传任何地方。

## 怎么用

1. 双击 `index.html`，用 Chrome 或 Edge 打开（不需要装任何东西，不需要联网）。
2. 上面选动作 → 点「+ 加动作」→ 填重量和次数 → 点「保存这次训练」。
3. **找动作**：下拉框上面有个搜索框，输入名字里任意一段（比如「推」）就只剩匹配的动作；按回车直接加当前选中的那个，加完自动清空关键词。常练的动作排在前面。
4. 单位：右上角的 `kg | lb` 决定**新加的组**默认用哪个。每组左边那个小按钮可以单独切换这一组——同一次训练里一台磅器械、一台 kg 器械也没问题。已有记录不会因为切换而被改写。
5. 想记体重：在「体重」卡片填日期和数字，点保存。同一天再存会覆盖，不会堆两条。
6. **记有氧**：在「有氧」卡片选类型（跑步/快走/骑车/游泳/划船机/椭圆机/跳绳）、填分钟数、选强度，有距离意义的项目还能填 km。同一天可以记多条。
7. 热量是自动算的：填完组数，动作下面会出现「本次 N 组 ≈ X kcal（逐组 8 / 14）」；有氧记完也会显示 ≈X kcal。见下面「热量怎么估的」。
8. **按天看**：「某一天」卡片里选日期，或用 `←` `→` 一天天翻，能看到那天练了什么、有氧做了什么、消耗多少（力量和分有氧分开列）、当天体重。下面「历史（按天）」是一天一块，点某一天就跳到它的详情。
9. 存错了想删：训练和体重在「某一天」/「体重」卡片里删，有氧在「有氧」卡片里删。**删了没有回收站**，点之前会弹确认框。
10. 想看曲线长什么样，在地址栏加 `?demo=1` 打开预览（示例数据不会保存）。

手机上用的办法：先把这些文件放进手机能访问的位置，再用浏览器打开。更省事的做法是把这个目录用一条本地服务器托管，然后在手机浏览器里「添加到主屏幕」，用起来跟 App 一样。

## 怎么验证它是对的

```bash
# 1. 逻辑测试：不需要装任何依赖
node test/logic.test.js

# 2. 真浏览器验证：会自己起服务器、点一遍、截图到 shot/
node test/browser-check.mjs
```

两个都得绿了才算改完。这是「改一行就跑一遍」的成本下限——低于这个成本，人就不会去验证。

## 数据存在哪

浏览器 localStorage，四个键分开存：

| 键 | 内容 |
|---|---|
| `fitness-tracker-v1` | 训练记录（动作、组、重量、次数、**每组的单位**） |
| `fitness-tracker-weight-v1` | 体重记录（每天一条） |
| `fitness-tracker-cardio-v1` | 有氧记录（类型、时长、强度、距离） |
| `fitness-tracker-unit-v1` | 单位偏好：新组默认用 kg 还是 lb |

三类记录（训练 / 体重 / 有氧）形状差别太大，故意分成三个键：一个是「组×重量×次数」，一个是「一天一条数」，一个是「类型+时长」。混在一个数组里，每次读写都要先判断类型，越用越脏。

关于单位，两条规则记住就不会错：

- **存的是你输入的数字 + 原始单位**，不存换算后的 kg。所以在磅器械上记「111」，回头看到的就是 `111lb`，不会被改写成 `50.3kg`。
- **容量和 PR 比较时统一换成 kg**（1 lb = 0.45359237 kg）。所以总容量永远标 `kg`，混合单位的记录也能放在同一把尺子上比。
- 切换某组的单位按钮会换算数字（111lb ↔ 50.3kg），来回点不会累积误差——内部留着一个精确的 kg 值。

容量上限约 5MB，按现在的记录量够用很多年。

**会丢数据的三种情况**：换电脑、清浏览器缓存、用无痕模式。所以有个「导出 JSON」按钮，想换设备前点一下。

导出的文件是 `{app, version:3, exportedAt, sessions, weights, cardio}` 结构，一次带走三类数据。导入三种格式都认：旧版纯训练数组、v2 的 `{sessions, weights}`、v3 带 `cardio` 的。导入是合并、不覆盖；同一天的体重以本地记录为准，有氧按「日期+类型+时长+强度」去重。

## 热量怎么估的

公式是 `kcal = MET × 体重(kg) × 时长(小时)`，用的是运动生理学里常用的代谢当量（MET）估法。

三个输入：

| 输入 | 取值 | 说明 |
|---|---|---|
| MET | 按「单组重量 ÷ 体重」分三档：轻 3.5 / 中 5.0 / 强 6.0 | 依据《体力活动纲要》对轻中强抗阻训练的三档划分 |
| 体重 | 训练当天或之前最近一次的体重 | 三个月前 78kg 时练的，不按今天的 75kg 算；没有体重记录时按 70kg 兜底 |
| 时长 | 每组 2 分钟（含组间休息） | 故意写死，因为让你每组填时长会让记录成本翻倍 |

**强度档怎么判**（`单组重量 ÷ 体重`，所以同样 60kg，体重 60kg 的人和 90kg 的人档位不同）：

| 相对负荷 | 档位 | MET | 例：72kg 的人 |
|---|---|---|---|
| < 0.3 | 轻 | 3.5 | 20kg 卧推 → 每组 ≈8 kcal |
| 0.3 – 0.6 | 中 | 5.0 | 30kg 卧推 → 每组 ≈12 kcal |
| ≥ 0.6 | 强 | 6.0 | 60kg 卧推 → 每组 ≈14 kcal |

**自重动作**（重量填 0）没法算相对负荷，按动作类型给固定值：复合 8.0、半复合 5.0、孤立 3.5。

**这个估算的局限：**

1. **重量影响是「跳档」的，不是线性的**。20kg 和 29kg 都是轻档、算出一样的数；跨过 0.3 那条线才会跳到中档。这是分档法的代价，但至少重量真的会影响结果了。
2. **误差可能有 ±30%**。所以界面上一律标「≈」。
3. **它算的是运动中的消耗**，不含「运动后过量氧耗」（EPOC）那种事后持续燃烧的部分。
4. 为什么不按物理「举起了多少功」算：那个量太小。卧推 60kg×12 的机械功约 0.9 kcal，而一组总消耗约 14 kcal，举铁只占 5%，用物理功会让重量几乎不影响结果。

想要更准，唯一有效办法是记录每组的实际时长，而不是继续调公式。

### 有氧怎么算

同一个公式，只是 MET 换成有氧项目的值，时长换成你填的分钟数：

`kcal = MET(项目) × 强度系数 × 体重(kg) × 分钟 / 60`

| 项目 | MET（中等强度） | 说明 |
|---|---|---|
| 跑步 | 8.3 | 纲要里约 8 km/h |
| 快走 | 4.3 | 约 5.6 km/h |
| 骑车 | 6.8 | 中速 16–19 km/h |
| 游泳 | 5.8 | 自由泳中等 |
| 划船机 | 7.0 | 中等阻力 |
| 椭圆机 | 5.0 | |
| 跳绳 | 11.8 | 中等速度 |

强度系数：低 `0.8`、中 `1.0`、高 `1.25`。这是对 MET 的粗调——纲要本身就是按速度分档的，所以档位比精确值更可信。

**距离填了不用在公式里**，只是记录：热量只跟「项目 + 强度 + 时长 + 体重」有关。想按速度细分（比如 6 分配速 vs 4 分配速跑步），那要按距离/时间算出速度再查表，属于下一步的事。

有氧和力量的热量在「某一天」里**分开列**：`力量 ≈60 + 有氧 ≈311 kcal`。合成一个总数会让人以为有氧白练了。

## 想改东西的时候

改哪个文件，看你要改的是「算」还是「看」：

- 计算规则（多算一个指标、PR 换别的口径、加体重记录）→ 改 `logic.js`，然后补一条测试到 `test/logic.test.js`。
- 界面（配色、布局、多一个按钮）→ 改 `index.html` 里的 `<style>` 和 `app.js`。
- 默认动作库 → `logic.js` 顶部 `DEFAULT_EXERCISES` 数组，加几个字符串就行。

改完记得跑上面那两条命令。

## 已知的坑

- 日期用的是本机时区，跨时区旅行时「今天」可能跟你以为的不一样。
- 同一个动作在同一天记两次，会合并成一次训练（不是 bug，是故意合并的）。
- 曲线显示的是「当天最好一组的重量」，不是容量；容量在历史列表里。
- 体重一天只留一条：同一天再存会覆盖。想记「早晚各一次」目前做不到，也不建议——日间波动是水分，不是进步。
- 体重只有 kg，没有磅（器械重量才有 kg/lb 切换）。体重和器械重量是两套单位设置，别混。
- 容量（训练量）永远是 kg，即使你在用磅记录。因为要把不同单位的记录放在一起比，只能统一到一把尺子上。
- 图表画的是「当天的显示单位」，切到 lb 时曲线会整体换算成磅，形状不变。
- 热量是估算，不是测量：误差可能 ±30%。
- 热量按「相对负荷」跳档，不是随重量连续变化：20kg 和 29kg 都是轻档、数字相同，跨过 0.3 才会变（见「热量怎么估的」）。
- 你自己加的自定义动作没有类型信息，按「半复合」（5.0 档）处理，相对负荷分档对它照样生效。
- 自重动作（重量填 0）走类型固定值，不参与相对负荷分档。
- **删除训练没有回收站**，删掉就没了。想要后悔药，删之前先点「导出 JSON」。
- 同一天记了两次训练会显示成「第 1 次 / 第 2 次」，但不再是两条历史，而是一块里两段。
- 「某一天」里如果那天没称体重，显示「体重未记录」；算热量时仍用最近一次的体重，界面上会写明「按 XXkg 估」。
- 有氧的**距离不参与热量计算**，只作记录。热量只跟项目、强度、时长、体重有关。
- 有氧的强度系数（0.8 / 1.0 / 1.25）是粗调，不是精确分级；同一条跑步，选「中」和「高」差 25%。
- 有氧记录没有 id，导入去重靠「日期+类型+时长+强度」。所以你同一天认真跑了两段完全相同的 30 分钟，导入时会被当成一条。
- 动作搜索只按**文字**匹配，不支持拼音首字母（输 `wt` 找不到「卧推」）。拼音要引库或手写对照表，跟「零依赖」冲突，需要再做。
- 搜索是「包含」匹配且区分大小写对中文没影响；输英文动作名时大小写要一致。
